# Context

## Glossary

### Illustration
A single entry in the collection. Consists of a JPEG image file and a paired markdown file with YAML frontmatter containing metadata (tags, aliases, prompt, model, style, color scheme). The canonical unit of the library.

### Prompt
The text instruction used to generate an illustration with DALL-E 3. Stored in illustration frontmatter. Whether prompts appear in the published site is controlled by a build-time flag — see `PUBLISH_PROMPTS` in `.env.example`.

### Contribution
A proposal for a new illustration. Submitted as a GitHub Issue. The owner generates, reviews, and merges all new illustrations — contributors do not submit images directly.

### Image Variant
A resized copy of an illustration generated at build time for a specific purpose:
- **Thumbnail** (~200×200): displayed in the Gallery grid
- **Display** (~512×512): shown in the Detail Panel
- **Download**: the size offered to users for download (configurable)

All variants are generated by the Build Step. The grid always uses Thumbnails — loading full-size originals in the gallery is not acceptable for performance.

### Alias
An alternate name for an illustration (e.g. "Brain", "Second Brain" for the AI illustration). Aliases are searchable and visible on the Detail Panel so users understand why a result matched their query. On the grid/card view they are invisible search fodder only.

### Tag
An additive label on an illustration. Multiple tags per illustration are allowed. Tags form a loose-but-curated vocabulary that grows with the library. No fixed taxonomy — new tags are introduced as needed. Human-readable display names are defined in `src/locales/tag-names.ts`; the raw tag IDs are stable identifiers used in URLs and filter logic.

### Gallery
The main page (`/`) of the Showcase. Displays all illustrations in a responsive grid/card layout with inline search and tag filtering. Key behaviours:
- **Search**: large text field, searches name + aliases + tag names in real time as the user types
- **Tag filter**: multi-select dropdown, combinable with search
- **Result count**: total illustration count always visible; filtered/search result count shown when active
- **Empty state**: explicitly indicated when no illustrations match
- **Card size**: 3 predefined sizes (S / M / L); max size is the Thumbnail resolution
- **Grid density**: 2 options (compact / comfortable) controlling the gap between cards
- **Favourites filter**: toggle to show only favourited illustrations, combinable with search and tag filter
- Responsive — works well on mobile

### Detail Panel
Per-illustration view triggered by clicking a card in the Gallery. Renders as a side panel or overlay while keeping the user on the Gallery page. The URL updates to `/illustrations/:slug` so the view is shareable and directly linkable. Displays: image (Display variant), structured metadata (name, aliases, tags, model, style, color scheme, accent colors, creation date, prompt if enabled), any free-form markdown body content, and an Action Bar.

### Action Bar
A dedicated area in the Detail Panel for user interactions with an illustration:
- **Download**: downloads the illustration at the configured Download Size
- **Favourite**: toggles the illustration as a favourite, persisted in browser local storage
- **Copy link**: copies a shareable URL to the clipboard

### Favourite
A user-side mark on an illustration indicating personal interest. Stored in browser local storage — requires no account and no server. Purely client-side state. Favourited illustrations can be filtered in the Gallery via a dedicated toggle.

### Site Structure
- `/` — Gallery
- `/illustrations/:slug` — Detail Panel (also accessible as a deep link)
- `/about` — Background, use cases, how to use
- `/contribute` — Contribution guide
- `/faq` — Frequently asked questions

### Deployment
Publishing the built Showcase to Vercel. Automatic on every push to `main`.

### Build Step
A script (`scripts/build-index.ts`) that runs before the React app builds. Reads all `meta/*.md` files, applies the `PUBLISH_PROMPTS` flag, generates all Image Variants (thumbnail, display, download) from the source assets, and outputs the Index and sitemap.

### Local-First Scripts
All build, validate, test, and lint operations are defined as npm scripts and run identically locally and in CI. CI calls the same scripts — there is no logic that only works in a specific CI vendor. Key scripts:
- `npm run dev` — local dev server (Vite)
- `npm run build` — full production build including Build Step
- `npm run lint` — ESLint + TypeScript type-check
- `npm run validate` — frontmatter validation across all meta files
- `npm run test` — unit tests (Vitest)

### Index
A build-time generated JSON file containing all illustration metadata. Consumed by the Showcase at runtime for search and filtering. Contains no image data — only metadata and asset paths.

### Showcase
The web application that presents the Library to the public. Built with React + Vite + Tailwind CSS. Read-only — users browse, search, filter, and download illustrations but cannot modify the Library through it.

### Color Scheme
Catppuccin Mocha — the same palette used in the illustrations. Key values: base `#1e1e2e`, text `#cdd6f4`, accent colors (Mauve `#cba6f7`, Blue `#89b4fa`, Teal `#94e2d5`, etc.). Using the same palette makes illustrations look native to the site. Supports both light and dark themes.

### Library
The full collection of illustrations, including all image files and their paired metadata files. The primary artifact of the project — the website exists to showcase it. The repo is the source of truth; illustrations are authored by adding JPEG + markdown files directly.
